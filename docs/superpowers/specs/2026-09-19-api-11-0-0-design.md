# packet_parser 11.0.0 — solder l'epic #76 (ruptures d'API)

Date : 2026-09-19 — Statut : design validé, en attente de relecture de la spec.

## 1. But

Livrer en **une seule majeure** toutes les ruptures d'API accumulées dans
l'epic #76 pendant la fenêtre de stabilité 10.x, et fermer la cause racine
qui les a produites : des types publics exhaustifs que l'on ne peut étendre
sans majeure.

Critère de succès : #76, #22, #26, #27, #32 et #82 fermées ; `cargo
semver-checks` ne signale aucune rupture qui ne soit pas décrite dans le
guide de migration ; le paquet de référence du bench ne régresse pas.

## 2. Hors périmètre

- ~~Décodage GIOP de `LocateRequest`, `LocateReply`, `CancelRequest`,
  `Fragment`~~ — **réintégré le 2026-09-19** à la demande du mainteneur
  (« GIOP complètement parsé, fiable ») : des captures réelles ont été
  trouvées (tracker Wireshark) et produites (labo omniORB). Voir §4 lot C et
  `pcaps_exemple/protocols/giop/SOURCE.md`.
- MIOP (UDP multicast) et ZIOP (GIOP compressé) comme protocoles détectés :
  ce sont des enveloppes distinctes de GIOP. `find_giop_message` permet déjà
  d'atteindre le message GIOP d'un datagramme MIOP.
- « Restreindre `protocols` » (#32) : les décodeurs sont le produit, ils
  restent publics.
- `#![deny(missing_docs)]` (#32) : pas une rupture, livrable en 11.x.
- Tag git, `cargo publish`, intégration dans `Sonar_desktop_app` : actions
  sortantes, déclenchées uniquement sur demande explicite une fois la PR
  finale relue.

## 3. Livraison

Branche d'intégration `release/11.0.0`. Une PR par lot vers cette branche,
puis une PR finale `release/11.0.0` → `main`. `main` reste publiable en
10.5.x pendant le chantier.

Ordre : **B → A → C → E → D → F**. La purge (B) passe en premier : elle
réduit la surface publique que les lots suivants doivent annoter et migrer.

Chaque lot : TDD, `cargo test`, `cargo clippy -- -D warnings`, `cargo fmt
--check`, compilation des cibles de fuzz, section « Rupture » du CHANGELOG et
paragraphe du guide de migration écrits dans la même PR.

**Écarts constatés à l'implémentation du lot B (2026-09-19)** :

- `checks::checksum` n'était pas du code mort mais une API opt-in annoncée
  au CHANGELOG : promue en `packet_parser::checksum` au lieu de disparaître
  avec `checks`.
- `Internet::try_from_parts` est **conservé**, contre #32 : sans appelant
  interne, mais c'est l'entrée que la doc du `TryFrom` aveugle recommande,
  et le pendant de `Transport::try_from_parts`.
- #26 : plutôt que d'instrumenter le chemin unique avec `time_block_ns!`
  (qui aurait fait payer `Instant::now()` à tout `parse()` dès que la
  feature est activée quelque part dans le graphe), le pipeline est
  générique sur un puits de mesures ; la macro exportée, sans appelant, est
  supprimée.
- Deux checks « morts » étaient de la logique dupliquée en ligne dans leur
  parseur (DHCPv6, FTP) : recâblés plutôt que supprimés.

### Lot A — Erreurs

- **#21** : `#[non_exhaustive]` sur tous les enums d'erreur de `src/errors`
  qui ne l'ont pas (45 sur 46 aujourd'hui).
- **#24** : `TcpError::InvalidFlags { flags: u8 }` et
  `TcpError::ReservedBitsSet { bits: u8 }` remplacent l'usage détourné de
  `InvalidHeaderLength`.
- **Politique SYN+FIN : conserver et signaler.** Un en-tête TCP
  structurellement lisible dont seuls les drapeaux (ou bits réservés) sont
  incohérents garde sa couche transport (ports, séquence, drapeaux), et
  l'anomalie est rapportée dans `corrupted` avec `layer: Transport`. La
  couche application n'est pas sondée sur un tel paquet. Le doc-comment de
  `CorruptedLayer` est mis à jour : la couche signalée est `None` pour une
  corruption *structurelle*, conservée pour une anomalie *sémantique*. Le
  test bout-en-bout de `3480f68` est retourné et complété (SYN+FIN, bits
  réservés, SYN seul intact).
- **Chemin d'erreur de liaison unique** : Ethernet rapporte
  `LinkLayerError::Truncated { link_type: ETHERNET, required, actual }`.
  `ParseError::InvalidDataLink` disparaît. `DataLinkError` survit hors de
  `ParseError` (erreurs de parsing MAC/STP) et devient `#[non_exhaustive]`.
  Un test paramétré vérifie le contrat de `sprint_02.md` §« Contrat
  d'erreur » sur les six LINKTYPE câblés.

### Lot C — Champs et variantes

- **`#[non_exhaustive]` étendu** (décision du 2026-09-19) :
  - tous les enums publics dont les valeurs suivent une spec évolutive
    (`IpType`, `CorruptedLayerKind`, `GiopMessage`, `GiopMessageType`,
    `TargetAddress`, `PostgreSqlMessageBody`, etc. — inventaire exhaustif
    fait à l'implémentation, liste reportée au guide de migration) ;
  - toutes les structs *borrowed* que seul le parseur construit
    (`PacketFlow`, `DataLink`, `Internet`, `Transport`, structs de décodage
    de `parse::application::protocols`).
  - **Exclues** : les structs de `owned` (Sonar les construit en littéral) et
    les newtypes/valeurs (`MacAddress`, `VlanTag`, `DnsType`, …).
- **#82 `vlan_stack`** : nouveau champ sur `DataLink` et `DataLinkOwned`,
  pile complète du tag externe au tag interne. La boucle de
  `parse::data_link` n'a pas de profondeur maximale (elle est bornée par la
  longueur de la trame), donc pas de tableau inline plafonné : côté borrowed,
  `vlan_stack: VlanStack<'a>` est une vue sur les octets de tags de la trame
  (`&'a [u8]`, déjà validés par `validate_data_link_vlan_stack_length`),
  avec `len()`, `is_empty()` et `iter()` qui rend des `VlanTag` — zéro
  allocation sur le chemin chaud. `Vec<VlanTag>` côté owned. `vlan` reste le
  tag interne. Sérialisé comme une liste, seulement s'il y a au moins deux
  tags. Golden : étendre `tests/qinq_golden.rs` (captures de
  `pcaps_exemple/vlan/`).
- **#9 `IpType::Broadcast`** : 255.255.255.255. La diffusion dirigée reste
  hors de portée (masque inconnu), comme documenté en `583a7d8`.
- **GIOP** :
  - `GiopReply<'a> { request_id: u32, reply_status: GiopReplyStatus,
    service_contexts: Vec<ServiceContext<'a>>, body: &'a [u8] }`, layouts
    1.0/1.1 (contexts en tête) et 1.2 (contexts en queue, body aligné sur 8).
    `GiopReplyStatus` : `NoException`, `UserException`, `SystemException`,
    `LocationForward`, `LocationForwardPerm`, `NeedsAddressingMode`,
    `#[non_exhaustive]`. Un body Reply illisible dégrade en `Other`, comme
    pour Request (le probe ne change jamais de classification).
  - `TargetAddress::ProfileAddr { tag: u32, profile_data: &'a [u8] }`.
  - `GiopRequest::requesting_principal: Option<&'a [u8]>` (`Some` en
    1.0/1.1).
  - `GiopParseError::UnknownTargetDiscriminator(u16)` : plus de saturation
    à 255.
  - Golden : trame 6 de `corba.pcap` (Reply 1.2 « No Exception », tient dans
    un segment). Trame 19 pour le `tag` TAG_UIPMC = 3.
  - **Extension du 2026-09-19 (livrée sur `feat/76-giop`)** : les huit types
    de message, `GiopReplyDetail` (exceptions, `LocationForward(Ior)`), module
    `ior` avec profil IIOP, `GiopPacket::truncated` (message débordant du
    segment accepté au lieu de rejeté), `giop_messages` / `find_giop_message`,
    `ProfileAddr(TaggedProfile)` et `ReferenceAddr { selected_profile_index,
    ior }`. Critère de fiabilité : parité avec tshark message par message sur
    tout le corpus réel (`tests/giop_tshark_regression.rs`), écarts nommés.

### Lot E — Schéma JSON unique (#22)

> **Décision inversée le 2026-09-20** : c'est le schéma *owned* qui fait foi,
> pas le *borrowed*. Mesuré à l'implémentation : le frontend de Sonar lit les
> clés owned (`source_ip`, `protocol_transport`… : 2-3 fichiers front, ~100
> références Rust) et **aucune** clé borrowed. Le texte ci-dessous est la
> version d'origine, conservée pour mémoire.

- Le schéma *borrowed* fait foi (`source`, `source_type`, `destination`,
  `destination_type`, `protocol_name`, `protocol`). Les types `owned`
  l'adoptent par `#[serde(rename)]` : **les noms de champs Rust ne changent
  pas**, seul le JSON produit change.
- `TransportOwned.protocol` est sérialisé comme le modèle borrowed.
- `Display` de `TransportProtocol::Tcp` redevient `"TCP"` ; le test de
  `parse/mod.rs` compare au `Display`.
- Test d'égalité `serde_json::to_value(&flow) ==
  serde_json::to_value(&flow.to_owned_flow())` sur le flux **complet**, pour
  au moins un paquet TCP, un UDP, un VLAN et un tunnel. Les écarts assumés
  (payloads absents du modèle owned) sont listés explicitement dans le test,
  pas masqués.

## 5. Gestion d'erreur et invariants

- Aucun parseur ne panique sur entrée arbitraire : toute nouvelle lecture
  passe par une fonction de `checks` avec arithmétique vérifiée.
- Un probe ne change jamais de classification parce qu'un body est mieux
  décodé : l'échec d'un sous-décodage dégrade, il ne rejette pas.
- Les compteurs déclarés par le paquet sont bornés par les octets restants
  avant toute allocation ou boucle.
